# nblaunch Open Questions, Assumptions, and Risks (Stage 01)

## Confirmed Assumptions
- [confirmed assumption] Notebook launch links are generated by a trusted upstream that shares `NBLAUNCH_HMAC_SECRET` with nblaunch.
- [confirmed assumption] JupyterHub is the source of truth for authenticated user identity and per-user home-subpath metadata.
- [confirmed assumption] nblaunch is allowed to write notebooks only inside configured notebook base directory and resolved user subpath.
- [confirmed assumption] `/oauth_callback` behavior primarily follows JupyterHub service OAuth machinery, not custom auth logic.

## Unresolved Decisions
- [unresolved decision] Exact Hub API field path for user home-subpath mapping (for example `auth_state`, custom field, or annotation-like key).
- [unresolved decision] Notebook filename policy on collisions (overwrite, suffix strategy, or reject with conflict).
- [unresolved decision] Whether `404` for missing user home mapping should instead be `422` to represent incomplete user provisioning.
- [unresolved decision] Whether gallery lookup should support notebook revisions/versions in `nb` contract.
- [unresolved decision] Final timeout and size-limit defaults for production (`NBLAUNCH_MAX_NOTEBOOK_BYTES`, timeout values).
- [unresolved decision] Required structured logging schema and audit fields for launch attempts.

## Risks Needing Validation
- [risk needing validation] Clock skew between link generator and nblaunch could cause elevated `401` rates if TTL is too strict.
- [risk needing validation] Hub API schema drift could silently break home-subpath resolution and surface as `502`/`404`.
- [risk needing validation] Large notebook downloads may cause memory pressure unless streaming and size checks are enforced early.
- [risk needing validation] Filesystem permission mismatches in real deployments may cause persistent `500` write failures.
- [risk needing validation] Service token scope could be over-broad; least-privilege scope must be validated during Hub integration.
- [risk needing validation] Redirect path construction bugs could create open-redirect or path confusion vulnerabilities.

## Human Review Needed Before Stage 02
- Confirm final status-code choices for `/launch` failure classes (`404` vs `422`, `502` usage boundaries).
- Confirm canonical HMAC signing format (`nb=<nb>&ts=<ts>`) with link-generator owners.
- Confirm authoritative Hub user-model field for home-subpath and ownership of that schema.
- Confirm notebook naming and collision policy.
- Confirm production defaults for TTL, size limits, and HTTP timeouts.
- Confirm required audit/event logging fields and retention expectations.
